### D-01: Чем генерируем proforma-инвойс?

Cart-summary редиректит на `/pages/thank-you`, но кто фактически делает PDF-инвойс?

**Опции:**
- **A.** Shopify Order Printer (бесплатное приложение от Shopify) — рендерит PDF из Liquid-темплейта
- **B.** Coгласовать с Massy — у них может быть встроенная генерация
- **C.** Сторонний invoice-app из Shopify App Store (платный, но настраиваемый)
- **D.** Кастомный — генерим PDF на стороне сервера через app proxy

**Рекомендация:** начать с (A) Order Printer — бесплатно и достаточно для MVP. Кастомный темплейт под B2B proforma пишется в Liquid, можно сделать многоязычным.

**Кто решает:** Маша

### D-02: Структура дашборда аккаунта

Сейчас есть дубляж: «Quick Reorder», «Invoice page», и третья похожая страница. Не понятно что где должно быть.

**Что нужно прояснить:**
- Какие 100% страницы должны быть в B2B-аккаунте?
- Какие из текущих — лишние и можно удалить?
- Какая иерархия в меню аккаунта?

**Предлагаемая структура (на обсуждение):**

```
/account                    ← Dashboard (overview: tier, открытые заказы, quick stats)
/account/orders             ← История заказов
/account/orders/<id>        ← Детали заказа
/account/orders/<id>/invoice ← PDF инвойса для скачивания
/account/reorder            ← Quick reorder (последние товары + 1-click добавление в корзину)
/account/profile            ← Настройки (управляется через Massy)
/account/addresses          ← Адреса доставки (если есть несколько)
```

**Кто решает:** Маша + аудит текущих страниц в репо

### D-06: WSP metafield — cents или CZK? ✅
**Решено:** **CZK** (display value). Пользователь подтвердил 2026-05-02.
**Действие:** все секции читающие `custom.wholesale_price` работают с CZK напрямую без деления на 100. Где-то уже могут быть деления — проверить и убрать.

### D-07: Checkout — `/pages/thank-you` или `/checkout`? ✅
**Решено:** **`/pages/thank-you`** (кастомный flow с инвойсом). Shopify Checkout не используется вообще.
**Действие:** убедиться что `/pages/thank-you` существует (см. BUGS.md #9), нет ссылок на `/checkout`.

**Действие:** убрать любую логику расчёта shipping в коде. В cart-summary и checkout — статичный текст.
