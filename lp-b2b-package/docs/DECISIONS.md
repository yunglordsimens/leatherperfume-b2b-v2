### D-01: Proforma-инвойс — чем генерируем? ✅
**Решено:** **Shopify Order Printer** (вариант A).
**Решил:** Маша (по рекомендации DS, 2026-05-02).
**Обоснование:** бесплатное официальное приложение Shopify, рендерит PDF из Liquid-темплейта. Достаточно для MVP.

**План имплементации:**
1. Установить Shopify Order Printer в админке (см. SHOPIFY-SETUP.md).
2. Создать кастомный Liquid-темплейт Proforma Invoice:
   - БЕЗ слова «Tax Invoice»
   - С пометкой «This is not a tax document»
   - Реквизиты Leather Parfum
   - PO Number
   - Условия оплаты (банковский перевод)
3. Сделать темплейт многоязычным (EN/CS/VI) через переводы.
4. После того как менеджер меняет статус заказа, Order Printer может авто-отправлять PDF клиенту.
5. Темплейт пишет DS, применяет CC.

### D-02: Структура дашборда аккаунта ✅
**Решено:** табовая структура внутри `/pages/partner-dashboard`, отдельные страницы для специфики.
**Решил:** Маша (по рекомендации DS, 2026-05-02).

**Финальная структура:**

```
/pages/partner-dashboard                  ← Dashboard overview (главная аккаунта)
/pages/partner-dashboard?tab=orders       ← История заказов (вкладка)
/pages/partner-dashboard?tab=invoices     ← Инвойсы (вкладка)
/account/orders/{id}                      ← Детали заказа (нативная Shopify)
/account/orders/{id}/invoice              ← PDF инвойса (через Order Printer)
/pages/quick-reorder                      ← Quick Reorder (отдельная страница)
/account/profile                          ← Настройки (управляется Massy)
/account/addresses                        ← Адреса (нативная Shopify)
```

**Что удаляем (после аудита репо):**
- `/pages/invoices` (если есть отдельно) — функционал в дашборде, вкладка `?tab=invoices`
- `/pages/order-history` (если есть отдельно) — функционал в дашборде, вкладка `?tab=orders`
- Любые третьи дублирующие страницы из тех что упоминала Маша

**Что проверяем:**
- В `dashboard-content.liquid` вкладки Orders и Invoices работают
- `/pages/quick-reorder` существует и имеет свой темплейт

**Кто делает:** CC (аудит + удаление дублей), DS (если нужны фиксы логики табов).

### D-04: Massy B2B — границы ответственности ✅
**Решено:** разделение зон зафиксировано.
**Решил:** Маша + DS (2026-05-02).

**Что делает Massy:**
- ✅ Регистрация / login форма
- ✅ Apply for Partnership форма
- ✅ Выдача тегов (`wholesale`) и метаполей после апрува

**Что делаем мы (тема):**
- ✅ Profile-страница — наш UI, данные из Shopify API через Massy-теги
- ✅ Дашборд — полностью наш
- ✅ Каталог, корзина, кастомный checkout — полностью наши
- ✅ Отображение цен и discount tier — наша логика в Liquid

**Что НЕ делает Massy:**
- ❌ Не рендерит инвойсы (это Order Printer)
- ❌ Не управляет отображением цен (это мы)
- ❌ Не управляет UI дашборда (это мы)

**HTML формы Massy:**
- Massy встраивает форму через App Block или шорткод в `massy-form-wrapper.liquid`
- Для фикса phone field overlap (BUGS #5) нужны точные классы/ID из браузера

**План фикса BUGS #5 (phone overlap):**
1. Маша открывает Apply for Partnership в инкогнито
2. F12 → находит input телефона и его label
3. Копирует HTML кусок (один input + label) и шлёт DS
4. DS даёт точный CSS-фикс
5. CC применяет в `massy-form-wrapper.liquid`

**Решено:** **ручное присвоение** для MVP (вариант A).
**Решил:** Маша (по рекомендации DS, 2026-05-02).
